# ADR 0001: URLと端末時刻を唯一の基準にする

状態: 採用（2026-09-12）

## 背景

TimeParioは最大3時計を比較してURLで共有する初期版。時刻の正確性、読みやすさ、軽量性を優先し、DB・保存API・日時ライブラリを導入しない。

## 決定

- 永続的な設定はURLのみ。`/`は自動判定モードとして残し、明示URLの時計と順番は端末設定より優先する。
- 正規化は定義した5短縮名と対応IANA IDに限定する。未定義の別名はIntlで検証して入力名を保持する。`resolvedOptions()`の別名変換は実行環境差があるため正規化に使わない。
- URL解析は共有の純粋関数に集約する。サーバーで検証済みのZoneは安全にシリアライズし、ブラウザー側で非対応でも共有・並べ替えを妨げない。新規入力の妥当性はIntlコンストラクターで確認する。
- 時刻は毎回端末の現在時刻を取得して再計算する。1回の描画のすべての時計には同じDateを渡し、秒の加算で進めない。日時変換・夏時間はIntlに任せる。
- UIは英語辞書と明示ロケールを使い、タイムゾーンと独立させる。
- Hono JSXはサーバーでのみ動作する。ブラウザーにはDOM操作コードのみを配信する。画面シェルは `src/client/shell.tsx` にUI文言とともに置くが、serverだけがインポートし、ブラウザーバンドルには含めない。
- 静的ファイルはStatic Assetsへ任せ、未検証のURLをSPA fallbackで隠さない。ハッシュなしアセットは必ず再検証し、HTMLは保存させない。

## 結果と制約

地域のルールは実行環境のタイムゾーンデータ、現在時刻は端末設定に依存する。標準時同期は保証しない。これを画面とREADMEで明示する。PCで時計を整列し、小画面や文字拡大時には必要な縦スクロールを許す。設定変更時のみカードを構築し直し、毎秒はテキストとSVG属性だけを更新する。
